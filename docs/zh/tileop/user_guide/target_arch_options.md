# 目标架构选项

## 作用

目标架构选项用于指定当前 PTO 程序面向的目标平台。

不同目标可能在支持的类型、布局组合、操作约束和生成结果上存在差异，因此编译时应明确指定目标架构。

## 相关参数

- `--pto-arch=a1|a3|a5`

该选项默认值为 `a3`；未显式指定时，`ptoas` 按 `a3` 编译。

目标架构由 ptoas 的 `--pto-arch` 命令行参数指定，用户不需要在 PTO 程序的 module 中通过模块属性重复声明目标设备信息。

## 默认建议

如果程序明确面向某一目标，建议始终显式指定 `--pto-arch`，避免因为默认值变化导致结果不一致。

## 什么时候调整

建议在以下场景关注该参数：

- 同一份 `.pto` 需要面向不同目标验证
- 某个操作或类型组合在一个目标上可用、在另一个目标上不可用
- 需要比较不同目标下的编译结果

## 可观察到的效果

切换目标架构后，用户可能观察到：

- 某些程序在一个目标上可通过，在另一个目标上报错
- 某些布局或类型组合的接受范围不同
- 生成结果存在目标相关差异

## 常见用法

```bash
ptoas input.pto --pto-arch=a3 -o output.cpp
```

```bash
ptoas input.pto --pto-arch=a5 -o output.cpp
```

## 排查建议

如果同一份输入在不同目标上表现不一致，建议按以下顺序排查：

1. 先确认 `--pto-arch` 是否设置正确
2. 再检查程序是否使用了目标相关的类型、布局或操作组合
3. 最后比较两个目标下的编译结果和报错信息

### A1 SPMD DMA 偏移

A1 耦合核 dispatch 最多使用 8 个 block。DMA 可使用由 `pto.get_block_idx`、
正步长静态上界循环及整数算术推导的动态偏移；验证器必须证明非负、32 字节
对齐以及完整 tile 位于源视图内。未知参数、无法证明的上界和算术溢出仍被拒绝。

### A1 动态 UB 槽位

完整静态 Vec 分块可使用运行时 UB 地址；验证器必须证明地址非负、32 字节对齐，
且整个分块位于 128 KiB UB 内。常量正数取余和有界循环可表达轮转槽位；未知、
未对齐或越界地址仍被拒绝。自动同步保守地将动态本地地址视为与同地址空间中的
其他分块可能重叠，因此不保证不同槽位之间的搬运与计算重叠。

完整静态 Mat 分块也可使用运行时 L1 地址；验证器须证明地址非负、512 字节对齐且
完整分块位于 512 KiB 配置预算内。自动同步同样保守处理动态地址别名，不保证
双槽位重叠执行或性能收益。ConvTile 图像分配以及 Left、Right、Acc 地址仍要求静态。

### A1 未使用的张量视图

平坦 ABI 参数生成的未使用视图 (unused tensor view) 不产生 DMA，可在存在
二维别名视图时保留。所有被消费的视图仍执行原有维度、布局、对齐和边界检查；
此支持不允许一维 DMA。

### A1 多 K GEMM

A1 允许公共 FP16 `M x K` Left、`K x N` Right 和 FP32 `M x N` Acc，N 为 16 或 32，M/K 为
[16, 2048] 内的静态 16 对齐维度，有效形状必须完整。Mat 可以使用 ZZ 或 NZ，
多 K Left 必须使用 ZZ；既有 NZ Left 仅在 K=16 时有效。Right 为 ZN，Acc 为 NZ。
分配及地址按每个块的实际形状和元素大小验证对应 L1/L0 存储预算，避免固定列数
低估缓冲区。N 不为 16 或 32、部分有效 tile 及无法证明安全的 DMA 仍被拒绝。

此路径需要支持多 K 的 A1 PTO-ISA `TLOAD`、`TMOV`、`TMATMUL` 和
`TMATMUL_ACC` 实现；仅升级编译器无法让旧 ISA 头文件接受宽 K。
硬件 im2col 的 ConvTile 编译已支持；PyPTO 前端接入仍需独立支持。

N32 Acc 可通过 `pto.subview` 选择静态、对齐且覆盖全部 M 行的单个 N16 列块，
然后复用现有 N16 Acc→Vec 写回；短行、动态列偏移和其他存储空间的子视图会被
拒绝。视图保留父块别名以维持自动同步。N32 路径需要配套支持 N32 Right 搬运
和矩阵乘的 A1 PTO-ISA；PyPTO 前端和整模接入仍需独立支持与验证。

原生组合回归位于 `test/npu_validation/scripts/test_a1_multi_k_gemm.py`。
设置 `PTO_ISA_ROOT` 指向上述 ISA 实现后，使用 `python -m pytest` 和 `-n 1`
运行该文件。CPU 检查同时启用 cube/vector 代码段，随后在 310P 耦合核上验证同一
生成代码；无设备或缺少对应 ISA 路径时跳过。

### A1 UB 到 L1 搬运

A1 `pto.tmov` 支持完整静态 FP16 Vec 到同形状 ZZ/NZ Mat 的搬运。Vec 必须为连续
行主序，M/K 均按 16 对齐；原有 UB/L1 容量检查保持生效。生成代码通过 MTE3
将 ND 行重排为 C16 面板，不经 GM 中转，也不执行标量 UB 读取。自动同步跟踪
V/MTE2 到 MTE3 的生产依赖、MTE3 到 MTE1 的消费依赖及缓冲区复用依赖。
此路径需要配套支持 Vec-to-Mat 的 A1 PTO-ISA。FP32 源、部分有效形状和累加器
专用模式不属于该搬运配置，A3 的地址空间支持范围保持不变。

### A1 C16 面板插入

A1 `pto.tinsert` 支持完整 FP16 C16 Mat 面板到完整 ZZ Left 块的子区域插入，
通过 MTE1 保留目标中未覆盖的值。K16 Left 仍可使用旧 NZ 布局；原有 L1/L0A
容量检查保持生效。行/列偏移必须能证明非负、按 16 对齐且完整面板位于目标内。
循环中的仿射偏移可使用，未知偏移和辅助量化/激活模式会被拒绝。该路径需要配套
A1 PTO-ISA 面板插入实现，自动同步跟踪 L1 生产、MTE1 读取及 Cube 消费依赖。

### A1 逐元素最大值

`pto.tmax` 支持形状一致的完整静态、行主序 FP16/FP32 Vec 分块，自动同步采用 V 流水。
列主序紧凑归约列不能直接用于该逐元素操作。需使用配套的公共 A1 `TMAX` ISA；
其目标可与任一输入精确同址，偏移重叠由 ISA 拒绝。原生回归先运行发射代码的 CPU oracle，再检查设备输出及哨兵。

### A1 零拷贝 Vec reshape

`pto.treshape` 支持同元素类型、同元素数的完整静态 FP16/FP32 Vec 行主序视图。
两端必须无盒式布局、无填充、每行按 32 字节对齐，并满足 128 KiB UB 限制。
输出别名到输入；连续 reshape 的同步依赖沿原始存储传播，无额外 DMA 或向量复制。
紧凑列、矩阵空间和类型重解释不在此支持范围内，需要配套 A1 `TRESHAPE` ISA。

### A1 FP32 UB 标量访问

`pto.tgetval` / `pto.tsetval` 支持完整、连续行主序 FP32 Vec 块，映射到公共
Tile `GetValue` / `SetValue`，由自动同步插入 V/MTE 与 S 流水线的依赖。
动态索引必须由调用者限制在块内；FP16、紧凑列和矩阵空间不在当前支持范围内。

### 标量舍入边界

浮点标量 SSA 运算保持独立的 C++ 语句，避免表达式合并后将补偿算法中的乘法和
减法收缩为 FMA。浮点标量类型转换同样保留具名值及完整操作数，防止 C 风格 cast
在嵌套算术表达式中仅作用于首项。该规则不改变向量或 Cube 指令的发射。

### A1 图像搬运与随路 im2col

`pto.tload` 可将静态 FP16 NC1HWC0 图像或按 C16 对齐的 NHWC 通道切片和完整宽度
行带搬入 Mat；图像分配、偏移和步长受 L1 容量与 DMA 描述符边界约束。
`pto.timg2col` 使用 FMATRIX A 自动配置和硬件 LoadData3DV2，将图像展开至 ZZ Left。
M/K 窗口必须能证明在范围内，K 按 16 对齐；编译器自动跟踪搬运、Cube 计算和
同一 Left 块复用时的依赖。该路径需要配套支持 NHWC 图像搬运的 A1 PTO-ISA。
不支持的布局、动态未知窗口和非默认 repeat 模式会被拒绝。
